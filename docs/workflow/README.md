# ワークフロー概要
このディレクトリでは開発作業ごとの進め方ドキュメントを管理します

## NOTE: このディレクトリで実装予定の内容(実装用の簡易TODO。終わったら削除する)
- design-workflow.md: 以下は設計ワークフローの内容箇条書き
  - 調査タスク: 調査メモ(docs/investigation) ディレクトリ配下に、調査メモmdファイルを作成する。ここでは実装内容について方針や制約、代替案などを議論した内容が出力される。調査メモの内容は設計メモ作成時にのみ参照され、使い捨てとなる。最新の仕様を把握するために read されない
  - 設計タスク: 設計メモ(docs/design-notes) ディレクトリ配下に、設計メモmdファイルを作成する。設計メモには "実装背景 Why", "実現したい内容 What", "実装内容 How", "代替案と却下理由 Why Not", "フェーズ別作業内容と完了条件 Plan" を全て含める
  - 設計レビュータスク: 設計メモの内容を次の観点でレビューするエージェントをSKILL経由で起動する。 1. 変更対象の spec ファイルが実装内容と合致しているか 2. 現在の spec ファイルと矛盾する前提を元に実装しようとしていないか
  - PR作成タスク: PRテンプレートに沿ってPRを作成する
- implementation-workflow.md: 以下は実装ワークフローの内容箇条書き
  - 実装タスク: 設計メモの内容をソースコードとして実装する。ビジネスロジック関数については単体テストを実装して検証する
  - spec/ADR昇格タスク: 実装後のソースコードが外から見てどのようなインターフェースを持っているかを確認して docs/spec ディレクトリ配下の spec ファイルを作成または更新する。また、設計メモの "代替案と却下理由" の内容を元に docs/adr ディレクトリ配下の ADR ファイルを作成する。その後は次の観点でレビューするエージェントをSKILL経由で起動する。 1. 更新した spec が ソースコードの挙動と合致しているかの整合性確認。 2. 更新したソースコードのdocstringやコメントが更新内容に追従できているかの整合性確認。 3. 作成した ADR がソースコードの方針と合致しているかの整合性確認。 それぞれレビュー時に指摘があれば修正する。レビュー完了後、設計メモは削除する
  - 実装レビュータスク: mainブランチとの差分内容について、各種コーディング規約ごとにレビューエージェントをSKILL経由で起動する。must指摘は修正し、should以下の指摘はユーザーに修正判断を委ねる
  - PR作成タスク: PRテンプレートに沿ってPRを作成する
