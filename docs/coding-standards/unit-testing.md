# 単体テストケース作成方針
## 単体テスト区分
- small: ビジネスロジック関数のテスト
- middle: I/O処理を含むコントローラー層関数のテスト
- large: 現在は未定義。より重い処理が実装された場合に適用する

## テストケースの作成ルール
- 単体テスト区分を @pytest.mark.small() などのデコレータで付与する
- テストケース名は "テスト対象関数が満たすべきビジネスルール" とする。 NG: テスト対象関数名、入力値、処理内容、期待値を並べたテストケース名
  - 良いテストケース名: 課題フィルタ_処理中タグが付いた課題だけに絞る
  - 悪いテストケース名: filter_issue_課題一覧を入力すると処理中タグの課題だけが含まれるリストを返却する
- テストコードは # Arrange, # Act, # Assert というコメントでブロック分割する
- Arrangeフェーズでは # 入力値の準備, # 期待値の準備 というコメントでブロック分割して入力値と期待値を準備する
- Act フェーズではテスト対象関数を1回のみ呼び出して返り値を取得する
- Assert フェーズでは返り値と期待値を比較してassertする

```python
@pytest.mark.small()
def test_テスト対象関数が満たすべきビジネスルール():
    """(検証するふるまいに関する説明)

    テスト観点:
        - (入力値や期待値をグルーピングする観点)
    """

    # Arrange
    # 入力値の準備
    param = "aaa"

    # 期待値の準備
    expectd = "bbb"

    # Act
    # テスト対象関数を呼び出して返り値を受け取るコード。Actフェーズは1行のみ
    actual = test_target_function(param)

    # Assert
    # 返り値を期待値と突合してassertするコード
    assert actual == expected
```
